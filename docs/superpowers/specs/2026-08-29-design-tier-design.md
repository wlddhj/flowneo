# FlowNeo 设计档位制（全量/精简）— 设计文档

日期：2026-08-29
状态：已与用户逐节确认

## 一、背景与目标

**问题**：02 四阶设计对「复杂但不涉及数据库/架构」的任务（算法实现、复杂前端交互、大规模重构）不够灵活——现有裁剪只有两档（Router 挡掉轻任务；`skipDesign=true` 整段跳过），中间地带缺失；且 02 的「笼统 vs 具体」示例全是 CRUD 视角，诱导模型硬凑数据库味内容。

**目标**：引入每任务级「设计档位」（全量/精简），在 01 阶段判定并记录、02 按档执行、Schema 校验按档放行。保持五阶段纪律与四段编号连续性，补上灵活性。

**已确认的关键决策**：

| 决策点 | 结论 |
|--------|------|
| 档位判定 | 模型按信号判 + 用户可否决（01 确认环节） |
| 判定信号 | 涉及数据表/对外接口/跨模块依赖 → 全量；纯逻辑/算法/UI 交互/重构/脚本 → 精简 |
| 记录位置 | 01 工件「## 设计档位」节（档位+理由）；02 工件头部一行「档位：…」标注 |
| Schema 感知 | 只看 02 单文件头部标注，不改 hooks 解析面 |
| 精简档形态 | 保留四段编号，第三阶改「技术要点」 |
| skipDesign 关系 | 正交：skipDesign=true 仍整段跳过 02，档位仅在 02 执行时起作用 |
| 配置化默认档 | 不做（YAGNI，留后续演进） |

## 二、变更内容

### 1. 01 技能（skills/01-need-explore/SKILL.md）

**执行步骤**：步骤 4（不确定项确认）之后、步骤 5（写模板）之前插入：

> **设计档位判定**：按判定信号选档——涉及数据表/对外接口/跨模块依赖 → `全量`；纯逻辑/算法/UI 交互/重构/脚本 → `精简`；判定理由一句话。用户显式指定档位时以用户为准并注明「用户指定」。

**模板**新增一节（「## 验收标准」之后、「## 待确认问题与结论」之前）：

```markdown
## 设计档位
- 档位：<全量 | 精简>
- 理由：<判定信号一句话；用户指定时注明>
```

### 2. 02 技能（skills/02-design-plan/SKILL.md）

- **步骤 1** 扩展：读 01 时同步读取「## 设计档位」节；无该节（旧任务）默认全量
- **步骤 2** 改为：按档位完成设计——全量档四阶完整；精简档保留一、二、四阶，第三阶写技术要点（关键决策、风险与应对、复杂度/性能要点）
- **自我评审第 3 项**分支：全量档「架构/数据设计支撑功能设计（模块/表/接口与业务流程对得上）」；精简档「技术要点覆盖本任务主要技术决策与风险，无遗漏关键项」
- **步骤 5** 扩展：写入工件时头部标注档位
- **模板**：标题下方加一行 `档位：<全量 | 精简>`；第三阶二选一：

```markdown
## 三、架构/数据设计（定底层）        ← 全量档（现状不变）

## 三、技术要点（定关键）              ← 精简档
- 关键技术决策：<选型/算法/取舍及理由>
- 风险与应对：<实现风险、边界条件>
- 复杂度/性能要点：<适用时写，无则标「无」>
```

- **HARD-GATE**：「适用档位的段落未齐全、且未经用户确认（或标注假设）前，禁止创建/修改任何业务代码文件。」
- **完成条件**第 1 条：「段落齐全（按档位：全量四段 / 精简含技术要点）且自我评审通过」
- skipDesign 提示行不动

### 3. Router（skills/_router/router.md）

skipDesign 提示行旁加一句：

> 用户显式指定设计档位（全量/精简）时，01 工件按指定记录「用户指定」；未指定由 01 按信号判定。

约 40 tokens；改后 `flowneo lint` 卡点必须仍过（≤1500）。

### 4. Schema 校验（src/lib/schema.ts）

- 02 章节清单按档二选一：两档共同必填「## 一、需求规格」「## 二、功能设计」「## 四、任务拆解」；全量档加「## 三、架构/数据设计」，精简档加「## 三、技术要点」
- `validateArtifact` 对 02 特殊处理：内容含 `档位：精简` 或 `档位: 精简`（全半角冒号、有无空格都认）→ 精简清单；其余（含 `档位：全量` 与无标注旧工件）→ 全量清单
- 只查缺失不查多余（如标精简却写了架构/数据设计标题不报错），维持 fail-open 纪律
- 数据结构调整方式（嵌套对象 vs 平铺条目）由实施计划决定，行为以本节为准

## 三、测试与验收

**测试**（tests/ 补 schema 用例）：
1. 全量档：四段齐 → 通过；缺第三段 → 警告
2. 精简档：含「## 三、技术要点」→ 通过；缺技术要点 → 警告
3. 无档位标注 → 回落全量清单（向后兼容）
4. `档位:精简`（半角冒号无空格）→ 识别为精简
5. 既有 77 测试回归全绿

**验收标准**：

| # | 标准 | 验证方式 |
|---|------|---------|
| 1 | 精简档 02 工件四段（含技术要点），Schema 校验通过无警告 | 测试用例 |
| 2 | 全量档与现状行为完全一致（旧任务不受影响） | 回归测试 |
| 3 | 用户显式指定档位时以用户为准并注明 | 技能文本审阅 |
| 4 | Router ≤1500 tokens、lint 通过、全部测试通过 | `npm run lint` + `npm test` |

**联动检查**：AGENTS-flowneo.md 若含 02 阶段描述须同步（lint 防漂移卡点会提示）；dist 产物随源码变更同步提交（verify 卡点）。

## 四、明确不做

- 配置化全局默认档（plugin.config.json stages 组扩展）
- 独立档位选择子技能
- 档位三档及以上细分
- 03/04/05 技能改动（档位只影响 02 工件形态；04 的「设计一致性比对」比对的是 02 实际内容，天然兼容）
