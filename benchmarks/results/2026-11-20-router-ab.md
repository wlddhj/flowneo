# A/B：Router 分流信号导向改造（v0.7.0 → v0.7.1）

## 改动

`skills/_router/router.md` 分流节等量替换：判据从「预判影响 ≤2 个文件」（想象题，agent 预判变更面本身不确定）改为**需求信号**（阅读题：新增功能/重构/接口/明言多文件即重）；重信号前置；「拿不准判重」保守倾斜；「判重后禁中途降级裸做，降级须落痕」并入重任务条。baseline/verbal 不受影响，复用首轮数据。

## 对照（flowneo 臂，GLM-5.3 / CC 2.1.133）

| 指标 | 首轮（旧分流） | 重跑（信号导向） | 变化 |
|---|---|---|---|
| heavy 工件完备均值（满 6） | 3.60 | **6.00** | +67%，30 格全部满配 |
| heavy 0 值格（工件=0，判轻裸做） | 12/30 | **0/30** | 清零 |
| heavy 命中率 | 92.7% | **97.4%** | +4.7pp |
| heavy 成本/格 | $1.26 | $1.80 | +43%（流程完整化的代价） |
| heavy turns/格 | 33.9 | 48.9 | +44% |
| light 命中率 / 工件 | 100% / 0.00 | 100% / 0.00 | 不回退（轻任务仍不建工件） |

逐任务：首轮 0 值的 multi-format-export 全部 6/6；首轮 2~4 的 cache/config/error/log/retry/validate 全部拉满；命中率除受 429 限流损伤、经补跑恢复的格（retry/refactor 部分轮次）外均满或近满。

## 结论

1. **遵循度问题被信号导向分流解决**：五阶段触发从随机（工件 0~6 参差）变为稳定（30/30 满配）——验收阈值（均值 ≥5.0、0 值格 0）达成
2. **质量随遵循度小幅上升**（92.7%→97.4%），首轮「流程半途而废」的格补全后命中提升
3. **成本上升 43%**：流程完整化的确定代价；结合首轮「质量三臂持平」结论，五阶段的价值判断回到产品定位层（护栏场景 vs 纪律场景），不在本任务范围

## 方法论备注

- 重跑期间遭遇 API 限额（429）：14 格受损被识别（流含 429 + 产出不完整）后删除补跑，最终数据 39/39 零失败；受损识别依赖「流文本含 429」与产出完整性双重信号
- 首轮 baseline/verbal 数据复用作对照（Router 改动不影响该两臂）
- 复现：`npm run bench -- --run --arms flowneo --runs 3 --stamp 2026-11-20-router-v2`；首轮快照 `runs/2026-11-20/`
