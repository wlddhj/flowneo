## 分析与局限

### 核心结论（可证伪设计下的如实呈现）

1. **漏需求率：三臂持平，FlowNeo 未显示优势。** 口径修订（分页解包兼容常见字段名、retry 模块路径放宽、refactor 主文件判定改折扣逻辑移出、cache brief 补清缓存需求）并 `--rescore` 离线重算后：baseline / verbal / flowneo 均为 93.5%（202/216，逐字相同）。排伪臂（verbal 一句话）同样无差异——在本任务集（强模型 + 口齿清楚的中小工单）上，质量天花板效应显著，工作流约束既未提升也未损害命中率。（残留 1 个全臂 0 命中点 cache-layer/clear-entry 系 brief 修订晚于跑格，agent 按旧 brief 未实现，不重跑。）
2. **成本：FlowNeo 为 3.2 倍。** flowneo 臂均值 $1.001/格 vs baseline $0.317（verbal $0.373）；turns 27.4 vs 9.9（2.8 倍）；时长 4.1min vs 1.4min（2.9 倍）。轻任务上纯为开销（light 三臂命中率同为 100%，flowneo 仍多付约 60% 成本）。停等确认续轮如实计入 flowneo 臂。
3. **流程遵循度不稳定——对 FlowNeo 最有行动价值的发现。** flowneo 臂工件完备数（01~05+status，满 6）在重任务上参差：cli-subcommand/refactor-extract 达 6.0，config-migrate 4.0、cache-layer/log-redact/retry-idempotent 仅 2.0，multi-format-export 0.0（被判轻量直接做）。同一套 Router 规则下，「重/轻分流」与「五阶段坚持」存在模型判断随机性——重任务域边缘的工单有时全流程、有时裸做。质量持平 + 成本 3 倍 + 流程时走时不走，共同指向：当前形态的 FlowNeo 在本档位模型上**收益未显现而成本确定**。

### 逐任务观察

- 口径修订前三处形态耦合（api 字段名 / retry 模块路径 / refactor 行数阈值）在三臂间同向误伤，修订后 api-pagination 与 retry-idempotent 均恢复至真实命中水平，且臂间仍无差异——印证「误伤同向、结论稳健」
- cache-layer `clear-entry` 为全臂 0 命中：brief 修订晚于跑格（旧 brief 未提清缓存），属跑格与口径的时间差，非能力差异

### 方法论局限

- 确定性检查点把「实现形态多样性」（字段名/文件名/结构）与「需求命中」混同：6 个检查点全臂全轮 0 命中，另有个别格级同向误伤——口径修订已消解主要形态耦合（93.5%），**臂间无差异的结论在修订前后均成立**（误伤同向作用于三臂）
- 13 张卡、单模型（GLM-5.3）、单机、3 轮：方差估计弱，不外推其它模型档位（弱模型上工作流的护栏价值可能显现，未测）
- 无 LLM 盲评（二期）：命中率是需求命中下界，不能区分实现质量的臂间差异
- srcLoc 的臂间对比参考价值有限：flowneo 产出含 test.js 与工件另计口径差异

### 对 FlowNeo 的迭代建议（基于本基准）

1. 分流判定与流程遵循的确定性：multi-format-export（3 文件变更）被判轻量、retry 流程半途而废，说明 Router 的「影响 ≤2 文件」规则在边界工单上执行不稳定——可考虑显式文件面清单判定
2. 若目标模型为强档位，五阶段的全量开销需要分级触发（如 skipDesign 默认化），否则 $0.7/格的价差难以由质量收益覆盖
3. 本基准框架已可复用（--rescore 改口径不重付费）：后续改 Router 后重跑同一矩阵即可 A/B 流程改进效果
